# Building

## 01_pdf

The source markdown in this directory is a verbatim transcription of the
official SRD PDF. It is **not** generated by any script in this repo — it is the
hand-verified input that everything downstream is built from. However it is
produced, the result must match the PDF exactly, because the extractors in
`02_csv` depend on its heading levels, stat-block shapes, and table columns.

### SRD 1.0 (DH-SRD-2025-09-09.md)

Produced with marker-pdf driven by an LLM, then extensively cleaned up by hand:

    pipx install --python python3.12 marker-pdf
    cd .build/01_pdf
    marker_single \
        --disable_ocr \
        --use_llm \
        --llm_service marker.services.openai.OpenAIService \
        --config_json marker_config.json \
        --openai_api_key "$OPENAI_API_KEY" \
        --openai_model gpt-5.1 \
        --timeout 180 \
        --max_concurrency 1 \
        --output_format markdown \
        --output_dir out \
        DH-SRD-2025-09-09.pdf
    cp out/DH-SRD-2025-09-09.md DH-SRD-2025-09-09.md
    npx --yes markdownlint-cli DH-SRD-2025-09-09.md

And then a lot of manual markdown cleanup...

### SRD 2.0 (DH-SRD-2026-08-25.md)

Marker was not used. The document was transcribed section by section directly
from `DH_SRD_2_2026_08_25.pdf`, cross-checking `pdftotext` output (for exact
characters) against the rendered page images (for bold/italic, heading levels,
and two-column reading order), and reusing the 1.0 markdown verbatim wherever
the 2.0 text was unchanged.

Conventions carried over from the 1.0 file: straight quotes and apostrophes,
the same heading hierarchy, the same table style, and printed typos preserved
exactly as they appear in the PDF (do not silently correct them).

Each section was verified against its page range by normalized bidirectional
text comparison (strip all non-alphanumerics, lowercase, compare both
directions), and the assembled document was checked the same way against the
whole PDF.

## 02_csv, 03_json, 04_md

    go run .build/02_csv/extract_from_md.go
    go run .build/03_json/extract_from_csv.go
    go run .build/04_md/extract_from_json.go

These three stages generate everything else in the repo: the CSVs, the JSON,
every content directory, and the root `README.md`. They are idempotent — after a
clean run, `git status` should report no changes. Never hand-edit generated
files; fix the extractor or the source markdown instead.

## Testing Static Site

    pipx install mkdocs
    pipx inject mkdocs mkdocs-material
    mkdocs serve

Note: `.build/04_md/docs/` contains symlinks to the content directories at the
repo root. On Windows checkouts with `core.symlinks=false` these appear as small
text files rather than directories, and a local build will produce an empty
site. Build on Linux/macOS, or let the CI workflow deploy.
